要旨Summary

スキーマの下で、LLM が公共データと照合した根拠付きの候補を返し、人が採否を決める設計において、都市環境メタデータ 175 行の検査の結果、2モデルは 99% 以上の正解率で動作した。 Under a design where an LLM returns evidence-backed candidates cross-checked against public data, and a human decides whether to accept them, inspection of 175 rows of urban-environment metadata showed two models operating at over 99% strict accuracy.

1

背景と目的Background & Purpose

都市の人工環境の表面は、ヒトと微生物が絶えず接触する主要な接点である。MetaSUB により都市間比較の基盤が整った一方（Danko et al., 2021）、国内の Urban microbiomes in Japan では、欠損、表記ゆれ、placeholder の混在が MIxS-BE 準拠と DDBJ 登録の障壁になっている（Tsujimoto et al., 2024；Glass et al., 2014）。LLM によるメタデータ整備の有効性も報告され始めた（Ikeda et al., 2025）。 Surfaces in the built environment are a primary contact point between humans and microbes. While MetaSUB established a basis for cross-city comparison (Danko et al., 2021), Japan's Urban microbiomes project has found that missing values, inconsistent notation, and stray placeholders are a barrier to MIxS-BE compliance and DDBJ registration (Tsujimoto et al., 2024; Glass et al., 2014). Reported benefits of LLM-based metadata curation have also begun to appear (Ikeda et al., 2025).

HITLの方法HITL Method

① 不整合を整形するスキーマを設計Design a schema that resolves inconsistencies

軸1 スキーマ設計Axis 1 — Schema design
  • 原値は保持し、規則で決まる値は正準列・ID列に別置きOriginal values kept; rule-determined values placed separately in canonical/ID columns
  • 機械的規則で決められない値はHITLに裁定を委ねるValues mechanical rules can't settle are deferred to HITL
  • 欠損はINSDC（International Nucleotide Sequence Database Collaboration）語彙で宣言するMissing values are declared using INSDC vocabulary (International Nucleotide Sequence Database Collaboration)
  • 実測値と予測値をあらかじめ分別できるように変数設計Variables designed so measured vs. imputed values can be told apart in advance

② スキーマへの変換を評価するデータセットDataset for evaluating the schema conversion

KoboToolbox 記録 5,655 行から東京 175 行 × 22 項目を抽出。各セルに期待行動（整合検査／宣言／候補提示／範囲外／対照行）を付与。参照データを固定：アメダス、国土数値情報、フォーム定義、ID参照ファイル。 175 Tokyo rows × 22 items were drawn from 5,655 KoboToolbox records. Each cell was assigned an expected action (consistency check / declaration / candidate / out-of-range / control row). Reference data fixed: AMeDAS, National Land Numerical Information, form definitions, an ID reference file.

③ 変換パイプラインとしてLLMの検査を設計Design the LLM inspection as a conversion pipeline

軸2 機械的変換規則＋公共データMCPAxis 2 — Mechanical rules + public-data MCP
  • 補完値の混入 → 原値との突合で検出Imputed-value contamination → detected by cross-checking the original
  • 信頼できない値 → 公共データで較正（アメダス・行政界・駅・路線）Unreliable values → calibrated against public data (AMeDAS, boundaries, stations/lines)
  • 近傍行は証人として参照（多数決にしない）Neighbouring rows consulted as witnesses, never a majority vote
軸3 LLMが根拠をもとに推論して候補を導くAxis 3 — LLM reasons from evidence to propose candidates
  • 誤用・自由記述・合成選択肢 → 文脈から分解候補Misuse, free text, composite choices → decomposed from context
  • 片側を正とできない矛盾 → 両論提示Contradictions with no clear right side → both presented
  • 候補に根拠・確信度を付す。既定欄は保持／宣言／隔離。書き換え禁止Candidates carry evidence + confidence. Default fields: keep / declare / isolate. Rewriting prohibited
今回の主な評価対象：Models evaluated: 4モデル（gpt-5.6-luna / Gemini-3.6-Flash / Claude-Opus-5 / Kimi-K3）に同一の指示書・10ツール・準拠ゲートで実行。 4 models (gpt-5.6-luna / Gemini-3.6-Flash / Claude-Opus-5 / Kimi-K3), each run with the same instruction set, 10 reference tools, and compliance gate.

LLMは現場記録だけからスキーマ案を作れるかCan an LLM draft a schema proposal from field records alone?

上記4モデルに、サンプル175行（G）か全5,655行の分布（F）のどちらかと、共通の国際規格（MIxS-BE、国際MetaSUB）の資料を渡し、35変数の設計書を計8本生成させた。条件Gでは値の事前入力の定義による予防性が支持された一方、条件Fではダミー値や未測位座標、Excel丸め残差、表記ゆれの吸収などの異常検出で高い成果が得られた。モデル間でも、積極的な導出・再設計を行うOpus、欠損値の回復規則を規約として考案するKimi、値の列挙に消極的なLuna、欠損値を欠損のまま置くGemini、と対応が分かれた。HITLで使ったスキーマは、それらの結果を参考に人が設計した。 The 4 models above were each given either a 175-row sample (condition G) or the distribution of all 5,655 rows (condition F), plus reference material for shared international standards (MIxS-BE, international MetaSUB), and asked to generate 8 design documents covering 35 variables in total. Condition G favoured preventive definitions of pre-entered values; condition F drew out strong anomaly detection — dummy values, unmeasured coordinates, Excel rounding residue, absorbed notation drift. Models diverged: Opus derived and redesigned proactively, Kimi devised missing-value recovery rules as convention, Luna was reluctant to enumerate values, and Gemini left missing values as missing. The schema used in HITL was human-designed, informed by these results.

考察、限界、展望Discussion, Limitations & Outlook

01

今回示せたことWhat this study showed

LLMの強みは文脈に応じて意味を再構成できる点にある。LLMは参照ツールで根拠を集め、規則では決められない値に候補と確信度を付けて返せた。候補と根拠の作成をLLMが担い、値の決定は人が行う分担で進められた。特にOpusでは、高い正解率に加え、推論による語彙の追加提案や、多様な観点からの問題検出が目立った。 The LLM's strength is reconstructing meaning from context. It gathered evidence with reference tools and returned candidates with confidence for values rules alone couldn't settle — the LLM builds candidates and evidence, a human decides. Opus stood out: high accuracy plus reasoning-driven vocabulary proposals and multi-angle problem detection.

02

スキーマ依存性Schema dependency

HITLの実現には適切な出力規約の設計が肝要であり、規約に隙があると、LLMはもっともらしい振る舞いでその隙を埋めてしまう。§4の未解消は、棄却時の既定値の任意記述を許可したことの影響で発生したと推察できる。本研究では厳密なスキーマと出力規約の設計によってこうした行動をある程度防いだが、この方法を広範なメタデータへ直ちに適用できるわけではない。 HITL hinges on a well-designed output convention — any gap in it, and the LLM will plausibly fill that gap on its own terms. The §4 unresolved cases likely stem from allowing free-text default values on rejection. Strict schema and convention design curbed this somewhat here, but the approach doesn't transfer immediately to broader metadata.

03

人の判断が必要な範囲Where human judgment stays essential

参照できる情報の外にある誤り（材質の現地確認や地下地上の区別など）と、どちらが誤りか決められない矛盾は人が決める。正解は規約が定めた期待行動への一致であり、値の真偽と人の作業時間は測っていない。 Errors outside referenceable information (e.g. on-site material checks, underground-vs-surface distinctions) and contradictions with no clear right side stay with humans. "Correct" means matching the convention's expected action — value truth and human working time were not measured.

04

未検証の効果と次の検証Untested effects & next steps

今後は、①来歴付き座標と3層地名による人口密度など公共統計との統合と地域層別化、②MIxS.me.built形式でのDDBJ実登録への展開、③フォーム自体の統合を実施し、例外値を自由記述から取得して動的にスキーマを更新するHITLサイクルの実現、に取り組みたい。 Next: (1) integrating provenance-tagged coordinates and 3-tier place names with public statistics such as population density, with regional stratification; (2) extending to real DDBJ registration in MIxS.me.built format; (3) unifying the forms themselves so exception values are captured from free text to dynamically update the schema — closing the HITL cycle.
